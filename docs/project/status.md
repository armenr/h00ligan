# Project status

Last verified: 2026-08-31

## Current state

h00ligan is physically reproducible as a four-crate standalone source workspace. The corrected
product source has passed the complete installed one-file product gate and cross-artifact
acceptance replay with Complete Calls authority for Rust, Go, Python, and TypeScript. The operator
has ratified a clean two-commit standalone import rather than filtered h00.sh ancestry.

This documentation reconciliation changes the native overlay and therefore requires one final
assembly, gate, and acceptance cycle before local Git preparation. Immutable external receipts,
not this self-contained page, determine whether that cycle completed. Candidate, artifact, and
acceptance identities remain outside the bytes whose identity they define; changing any source or
documentation invalidates acceptance and requires a new cycle.

The reconciled source layer contains 234 regular files. The separately authored native layer
contains sixteen files. Their exact identities and byte counts are held by external immutable
receipts to avoid a self-reference loop.

This source candidate:

- retains the `h00ligan`, `h00ligan-engine`, `h00ligan-interface`, and
  `h00ligan-provider-protocol` packages only;
- has no runtime dependency on h00.sh, Engram, or another h00 workspace package;
- exposes one exact 18-tool MCP registry;
- removes the unshipped `init`, `replace_symbol`, and `match` implementations and their orphaned
  support instead of hiding a second dormant registry;
- uses product-native `.h00ligan/performance` examples and neutral worktree prose;
- represents function-local interface methods and addressable anonymous-struct fields in Go while
  excluding generic type arguments from false interface-gap reports;

- reports the exact Rust-provider source root from the portable builder and requires the installed
  product harness to consume that result instead of guessing a source location;
- gives every standalone Rust-provider fixture its own explicit Cargo workspace so an enclosing
  monorepo cannot silently change fixture resolution;
- imports typed Go callable-liveness evidence without importing the h00.sh memory substrate;
- prevents the installed-product gate from writing Python bytecode into its source mirror and
  proves the mirror remains byte/mode exact after the complete gate;
- replaces the ancient-donor migration path with a bounded successor merge whose 11 controls bind

- separates product-candidate addressing from authority-receipt addressing, so authority-only

- restores borrowed, concurrent, overflow, and manually preempted WATCH hints across
  cancellation/supersession and removes an unreachable parallel population flag;
- makes the final product gate emit one typed receipt bound to the source tree, portable artifact,

- tightens assembly partition/accounting verification and acceptance replay, ordering, path, and

- packages current cargo-deny on Intel macOS through a pinned local Nix derivation instead of
  accepting the obsolete version available from that platform's final Nixpkgs branch.

## Release-readiness boundary

The standalone product is not release-ready until all of these are true for one exact final
candidate and artifact:

1. The native documentation and repository overlay are assembled with closed file accounting.
2. One acceptance manifest binds source, overlay, final candidate, build inputs, binary, product
   receipts, benchmark report, and residue verdict.
3. The complete standalone correctness and installed-product gates pass from that candidate.
4. Independent source/receipt audit passes.
5. The completed Anthropic Opus 5 and Z.AI GLM 5.3 max findings are closed against the newly
   assembled candidate, with correctness and deeper-design integrity kept as separate axes.
6. Exact source/context/genealogy/exclusion/secret manifests verify the ratified clean-import
   transfer boundary.

The history strategy is ratified, but no standalone commit, remote creation, Git cutover, release
tag, or publication has occurred. Final open-source licensing and macOS signing/notarization policy
remain explicit release decisions, not blockers to finishing the local candidate proof.
