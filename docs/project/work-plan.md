# Work plan

Last reconciled: 2026-08-31

This is the current standalone h00ligan sequence. Historical plans explain how the product arrived
here but do not override this order or live executable evidence.

## 1. Reseal the ratified transfer candidate

Current standing: the corrected product source and acceptance owners are complete and previously
passed the exact product gate. Ratifying the clean-import strategy changes four native documents,
so the closed 250-file assembly must be regenerated, gated, benchmarked, and replay-sealed once
more. Final container identities remain in external immutable receipts rather than inside the
candidate whose bytes define them.

- Complete the product-native documentation and repository overlay.
- Keep the source reconciliation and native overlay as separately identified inputs.
- Generate one immutable final candidate with closed file/mode/hash accounting.
- Publish an acceptance manifest that binds source, overlay, final candidate, build inputs,
  portable binary, product receipts, benchmark report, and zero-residue result.
- Run focused sabotage controls, then the complete source and installed-product gates.

Exit condition: a reviewer can reproduce every identity and cannot substitute, omit, replay, or
partially publish any accepted input without a failing control.

## 2. Verify the transfer boundary

- Generate exact manifests for the 234-file source commit, sixteen-file native commit, ignored
  context archive, parent genealogy, exclusions, secrets, path escapes, and local Git state.
- Prove the two commit populations are disjoint, complete, byte/mode exact, and union to the
  accepted 250-file candidate.
- Prepare a local repository with no commits or remote; verify ignored context cannot enter Git.
- Reconcile completed Opus 5 and GLM 5.3 review evidence. Any new external send requires exact
  operator authorization and keeps correctness separate from design integrity.

Exit condition: a reviewer can reproduce the clean import, cannot smuggle excluded parent state
into it, and cannot mistake archived genealogy for product authority.

## 3. Establish the standalone repository

- Use the ratified clean two-commit import; do not make filtered h00 ancestry a parent of `main`.
- Preserve verified parent anchors and receipts in tracked genealogy plus an ignored archive.
- After explicit authorization, create the two conventional commits and private remote, then
  establish default-branch protection, merge policy, controlled CI activation, and rollback state.
- Preserve the h00.sh tree and its unrelated dirty work. Removal from the incubator is a later,
  separately approved cleanup.

Exit condition: the accepted candidate has one canonical home and reproducible history without
copying h00.sh product policy or agent state.

## 4. Dogfood and evaluate at scale

- Install the accepted artifact and use CLI, MCP, and WATCH in real Rust, Go, Python,
  TypeScript, and polyglot repositories.
- Record misleading results, excess calls, setup friction, and authority misunderstandings as
  product defects.
- Run the task-level comparisons in the product evaluation contract.
- Improve agent integration from observed selection failures rather than mandatory hooks or a
  background service.

Exit condition: repeatable evidence that h00ligan improves real maintenance decisions, not only
that its tests are green.

## 5. Resume performance work

Profile first. The current measured mountains are whole-generation WATCH publication and cold
semantic-provider indexing. Prioritize owning-boundary changes such as incremental publication,
shared immutable projections, compiler-session reuse, and narrower invalidation.

Do not introduce sparse-matrix storage, semiring formulations, ring buffers, or other specialized
structures because they sound fast. Adopt them only when a profile identifies the matching
algorithmic or contention bottleneck and an installed-product A/B proves the gain without
weakening authority.

## 6. Finish distribution and developer experience

- Keep one-file Linux AMD64/ARM64 and macOS Intel/Apple-Silicon releases.
- Ratify licensing and macOS signing/notarization policy.
- Design managed Rust/toolchain acquisition around verified identities, explicit consent,
  offline behavior, pruning, and toolchain drift; do not put network acquisition inside the
  correctness-critical provider coordinator prematurely.
- Add languages or configuration breadth only with structural fixtures, semantic-provider
  authority, WATCH invalidation, installed-product acceptance, and performance controls.

Candidate future domains include PHP, SQL lineage, and shell/config relationships. They are not
promised until a concrete user question and truthful authority model are defined.
